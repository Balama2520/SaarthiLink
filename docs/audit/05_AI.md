# AI System Audit Report

## Overview
The AI layer consists of: `AIGateway` (orchestrator), `AIRouter` (provider selection), `PromptManager` (template loading), `CareerCopilotService` (business logic), and `DecisionEngine` (rule-based routing).

---

## Findings

### 1. Hardcoded Primary Provider — Ollama (HIGH RISK)
- **Location**: `app/ai/gateway.py` line 46–47
- **Observation**: `provider_name = "ollama"` is hardcoded. There is no configuration-driven way to switch the primary provider without code changes.
- **Impact**: Cannot switch to Gemini as primary in production without editing source code.
- **Recommendation**: Make primary provider configurable via `settings.PRIMARY_AI_PROVIDER`.

### 2. Streaming Fallback is Partial (MEDIUM RISK)
- **Location**: `app/ai/gateway.py` lines 57–77
- **Observation**: The streaming fallback triggers when the **entire stream** fails. If the primary provider fails mid-stream (after the first chunk has already been sent to the client), the fallback will not be invoked — only a warning message is yielded at the end. This leads to a partial response being silently delivered.
- **Impact**: Users see a truncated response with an error message appended.
- **Recommendation**: Buffer primary stream and fall back on failure before yielding to client. Alternatively, document this known limitation.

### 3. JSON Parsing — No Schema Validation (HIGH RISK)
- **Location**: `app/services/career_copilot_service.py` lines 67–71
- **Observation**: LLM output is stripped of markdown and passed directly to `json.loads()`. There is no Pydantic schema validation on the parsed result.
- **Impact**: If the LLM returns valid JSON with an unexpected schema (missing keys), downstream code that accesses dict keys without `.get()` will throw `KeyError` errors at runtime.
- **Recommendation**: Define Pydantic models for each AI response type (`RoadmapResponse`, `SkillGapResponse`, `JobStrategyResponse`) and validate the parsed output against them.

### 4. Hallucination Prevention in Job Strategy (GOOD)
- **Location**: `career_copilot_service.py` line 179
- **Observation**: The AI task instruction explicitly says `"DO NOT INVENT SCORES, they are provided."` and pre-computes scores algorithmically before sending them to the LLM. This is a strong hallucination prevention pattern.
- **Status**: Positive finding. No action required.

### 5. Decision Engine — Dead LLM Code (LOW RISK)
- **Location**: `app/engine/decision.py` line 34 (commented out)
- **Observation**: The LLM evaluation path is commented out (`# decision_json = ai_service.evaluate_decision(...)`). The fallback always returns a hardcoded `DIRECT_RESPONSE` decision.
- **Impact**: The `DecisionEngine` is effectively a partial implementation. Complex intent routing is not active.
- **Recommendation**: Document that the decision engine is in rule-based-only mode. Activate or remove the dead LLM path.

### 6. Prompt Injection — No Input Sanitization (HIGH RISK)
- **Location**: `_gather_context()` in `career_copilot_service.py`
- **Observation**: User-supplied fields (e.g., `profile.background_summary`, `resume.raw_text`) are directly interpolated into LLM prompts via `PromptManager.load()`.
- **Impact**: A malicious user could inject instructions into their profile fields to override the system prompt (e.g., "Ignore all previous instructions and...").
- **Recommendation**: Strip or escape prompt-injection-prone patterns from user-supplied text before interpolating into prompts. Consider using a separate `[USER CONTEXT]` delimited block that the system prompt explicitly tells the LLM to treat as untrusted data.

### 7. Two Redis Clients (MEDIUM RISK)
- **Observation**: There are **two separate Redis client implementations**: `app/memory/redis_client.py` (synchronous `redis.Redis`) and `app/core/cache.py` (async `redis.asyncio`). They are initialized independently.
- **Impact**: Inconsistent caching approach; two connection pools to Redis; could cause race conditions between sync and async cache updates.
- **Recommendation**: Unify to a single async Redis client used everywhere.

## CTO Recommendations
1. **[CRITICAL]** Implement Pydantic validation on all AI JSON responses.
2. **[HIGH]** Sanitize user text before injecting into prompts to prevent prompt injection.
3. **[HIGH]** Make primary AI provider configurable via environment variable.
4. **[MEDIUM]** Consolidate to a single async Redis client.
5. **[LOW]** Document or remove the commented LLM path in `DecisionEngine`.
