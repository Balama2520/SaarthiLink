# Development Workflow

This is where **gstack** fits in. Use it to guide development rather than changing Saarthi's architecture.

For every feature:

```
1. /office-hours
   Define the problem and requirements.

2. /autoplan
   Generate architecture and implementation tasks.

3. Implement the feature.

4. /review
   Perform code review.

5. /qa
   Test the feature.

6. /ship
   Prepare it for release.
```

This gives you a structured engineering process while keeping Saarthi AI focused on its mission.

## The most important rule

**Do not keep adding unrelated features.**

Every feature should answer one question:

> **Does this help a student or job seeker move closer to getting hired?**

If the answer is **yes**, build it. If the answer is **no**, leave it out of the MVP. That focus will make Saarthi AI far more valuable than trying to be another general-purpose AI assistant.
